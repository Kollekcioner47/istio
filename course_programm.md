Требуемые тематические блоки:
—	Инсталляция и архитектура Istio для эксплуатации: профили установки, ревизии, безопасное обновление и rollback без простоя сервисов.
—	Наблюдаемость (observability): мониторинг control plane и data plane (Envoy, istiod), метрики, логи, распределённые трейсы, дашборды и алерты, диагностика причин деградации.
—	Управление трафиком: маршрутизация (VirtualService/DestinationRule), timeouts/retries, обзор механизма xDS и lazy xDS; locality load balancing; circuit breaking; canary / A-B-выкатки; traffic mirroring.
—	Безопасность: взаимная аутентификация mTLS, политики доступа, контроль исходящего трафика; интеграция со SPIFFE/SPIRE и внешними секрет-хранилищами; онбординг stateful-компонентов (TCP-трафик, headless-сервисы).
—	Istio как API-gateway (Ingress/Egress): маршрутизация, CORS, проверка JWT/OIDC, rate limiting с внешними backend’ами, Lua-фильтры.
—	Multicluster и сетевые топологии (primary-remote, primary-primary, east-west gateway); Mesh Expansion — интеграция внешних виртуальных машин вне Kubernetes; диагностика связности, сертификатов и политик. Для этой темы требуется второй кластер K8s (master4 + node3).
—	Режимы sidecar и ambient: архитектура, сценарии применения, ограничения, сравнение по наблюдаемости и безопасности.
—	Системный troubleshooting: чек-листы диагностики, разбор инцидентов, подготовка пост-мортемов.
—	GitOps для управления Istio: ArgoCD Application и ApplicationSet, Git как единый источник истины для конфигурации mesh.
—	Performance tuning и тюнинг: HPA для istiod, resource sizing Envoy, оптимизация производительности, сравнение latency sidecar vs ambient.
Требования к практической составляющей:
—	После каждого тематического блока — не менее одной лабораторной работы на учебных стендах Исполнителя.
—	Наличие практики на симуляциях реальных инцидентов (поиск причины сбоя и восстановление работы системы), а не только учебных примеров.
—	Итог обучения — индивидуальное решение кейса по теме программы.
